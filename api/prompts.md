# Registro de Uso de IA (Copiloto)

Conforme o combinado da Global Solution (*"IA como copiloto: permitida para aprender e revisar"*), este arquivo registra os prompts que utilizamos no Claude (chat) para tirar dúvidas pontuais, revisar regras de DDD cobradas na disciplina e apoiar na documentação.

---

## 1. Revisão dos pontos descontados no CP4 e na Sprint 3

**Contexto:** Antes de começar a modelar as entidades do Telecentro, revisamos os feedbacks do Prof. Eduardo no Checkpoint 4 (FIAP Bank ATM) e na Sprint 3 (Challenge NORA) para não repetir os mesmos erros.

**Prompt usado:**
> "Estou montando a API Java da Global Solution de DDD (Spring Boot + JDBC puro no Oracle da FIAP). No CP4 e na Sprint 3 o professor descontou pontos por: usar record em entidade, deixar setter público (inclusive no id), usar Optional como atributo de classe, usar double em vez de BigDecimal para nota/valor e usar catch(Exception) genérico. Me ajuda a montar um checklist do que cuidar nas entidades Telecentro, Aluno, Lab, Avaliacao, Progresso e Tentativa seguindo o nosso script 01-ddl.sql?"

**Como ajudou e o que aplicamos:**
- Montamos a classe abstrata `EntidadeBase` com `id` final e `equals`/`hashCode` baseados apenas no `id`.
- Deixamos todas as entidades do pacote `model` como classes normais sem setters (mudança de estado apenas por métodos de negócio como `Aluno.desativar()`, `Progresso.concluir()` e `Telecentro.atualizarDados()`), usando `record` apenas nos DTOs (`Request` e `Response`).
- No `Aluno`, o atributo `email` foi mantido como `String` (podendo ser `null`), usando `Optional<String>` somente no retorno do getter `getEmail()`.
- Na `Avaliacao`, fizemos o cálculo da nota com `BigDecimal`, escala de 2 casas e `RoundingMode.HALF_UP`.

## 2. Dúvida de JDBC: recuperar ID gerado pelo Oracle (`IDENTITY`)

**Contexto:** As tabelas criadas em Database Design usam `GENERATED BY DEFAULT ON NULL AS IDENTITY`, e como o `id` na `EntidadeBase` é `final`, precisávamos recuperar a chave gerada no `INSERT` sem usar setter.

**Prompt usado:**
> "No Oracle da FIAP minha tabela T_ALUNO tem ID_ALUNO GENERATED BY DEFAULT ON NULL AS IDENTITY. Usando PreparedStatement no JDBC puro, se eu chamar RETURN_GENERATED_KEYS o driver do Oracle devolve o ROWID em vez do número do ID. Como faço pra pegar o ID_ALUNO certinho no getGeneratedKeys() e devolver o objeto Aluno com o id preenchido sem ter setId?"

**Como ajudou e o que aplicamos:**
- A IA explicou que no driver `ojdbc11` é preciso passar o nome da coluna da chave primária no array do `prepareStatement(sql, new String[] {"ID_ALUNO"})`.
- Aplicamos esse padrão nos DAOs (`AlunoDao`, `TelecentroDao`, `ProgressoDao`, `TentativaDao`) e, após ler o `rs.getLong(1)`, instanciamos e retornamos um novo objeto da entidade já com o `id` gerado pelo banco.

## 3. Tratamento de códigos de erro do Oracle no `@RestControllerAdvice`

**Contexto:** Queríamos evitar que erros de constraint do banco (como e-mail duplicado ou tentativa de excluir um telecentro que possui alunos) caíssem como erro 500 genérico.

**Prompt usado:**
> "Estou fazendo o TratadorDeExcecoes com @RestControllerAdvice. Quando o DAO pega uma SQLException do Oracle, quero olhar o getErrorCode() pra devolver o status HTTP certo (409 quando violar UNIQUE ou quando tentar deletar registro que tem FK apontando pra ele, 404 quando a FK não existir, 400 pra CHECK constraint). Quais são os códigos ORA- mais comuns pra esses casos?"

**Como ajudou e o que aplicamos:**
- Mapeamos no `TratadorDeExcecoes` os códigos do Oracle: `1` (violação de `UNIQUE` → 409), `2292` (registro pai com filhos dependentes no `DELETE` → 409), `2291` (chave estrangeira não encontrada → 404) e `2290`/`1400`/`1438`/`12899` (restrições de `CHECK`, `NOT NULL` e tamanho de coluna → 400).
- Criamos a `PersistenciaException` guardando o `codigoOracle` da `SQLException` para não precisar expor `SQLException` nas camadas BO e Controller.

## 4. Apoio nos testes unitários de domínio (JUnit 5) e cálculo de indicadores

**Contexto:** Testar as regras das entidades sem depender de conexão com o banco e revisar o agrupamento de tentativas por mês no `IndicadorBo`.

**Prompt usado:**
> "Me mostra como agrupar uma lista de Tentativa por ano/mês (formato yyyy-MM ordenado) usando Stream API em Java pra montar o mapa avaliacoesPorMes do indicador do telecentro, e sugere casos de borda pra eu testar no JUnit das entidades Aluno, Progresso e Avaliacao."

**Como ajudou e o que aplicamos:**
- No `IndicadorBo`, usamos `Collectors.groupingBy` convertendo `dataEnvio` para `YearMonth.from(...).toString()` com `TreeMap::new` para manter os meses em ordem cronológica.
- Nos testes JUnit (`AlunoTest`, `AvaliacaoTest`, `ProgressoTest`, `TelecentroTest`, `TentativaTest`), incluímos testes garantindo que `atualizarCadastro` e `atualizarDados` não alteram nenhum atributo se um dos campos for inválido, além de divisão não exata na nota (2 acertos em 3 questões = `6.67`).

## 5. Configuração do Dockerfile para o Render e diagramas PlantUML

**Contexto:** Preparar o deploy no Render (que não tem suporte nativo direto a Java sem Docker) e gerar o diagrama de classes para o PDF da entrega.

**Prompt usado:**
> "Preciso subir essa API Spring Boot (Java 21 + Maven Wrapper) no plano gratuito do Render usando Docker. Como monto um Dockerfile multi-stage enxuto e garanto que o LocalDate.now() use o fuso horário de São Paulo e não UTC?"

**Como ajudou e o que aplicamos:**
- Montamos o `Dockerfile` em duas etapas (`maven:3.9-eclipse-temurin-21` para o build e `eclipse-temurin:21-jre` para execução) passando `-Duser.timezone=America/Sao_Paulo` no `ENTRYPOINT`.
- No Render, configuramos o `server.port=${PORT:8080}` e o `server.forward-headers-strategy=framework` no `application.properties` para o Swagger UI e o header `Location` funcionarem em HTTPS.
- Também usamos o chat para revisar a sintaxe do PlantUML (`docs/diagrama-classes.puml`) a partir das classes que implementamos.
