A database starts as a drawing. For the OpenLabs telecentre, the drawing has
ten boxes (telecentres, monitors, learners, computers, handbooks, phases, labs,
assessments, progress and attempts) and ten lines between them. Each box lists
its attributes with their types, underlines the primary key, marks the foreign
keys, and each line says how many rows on one side match how many on the
other. That drawing is the relational model, and in Oracle SQL Developer Data
Modeler it can be drawn by hand or generated from an existing DDL file
([Data Modeler](#src-data-modeler)). Everything after it is a translation into
SQL.

## The diagram has to say five things

A diagram that leaves one of these out cannot be turned into a database without
guessing:

1. **Tables**, one per kind of thing, named `T_<NAME>` in this schema.
2. **Attributes**, each with a type: `nm_aluno VARCHAR2(80)`, `dt_cadastro DATE`,
   `vl_nota NUMBER(4,2)`. The prefix says what kind of value it is (`id_`, `nm_`,
   `dt_`, `vl_`, `st_`).
3. **Primary keys**, one per table, never repeated and never empty.
4. **Foreign keys**, the columns that hold another table's key.
5. **Relationships with cardinality**: `T_TELECENTRO 1 — 0..N T_ALUNO` (a
   telecentre may have no learners yet), `T_TELECENTRO 1 — 1..N T_MONITOR`
   (every telecentre has at least one monitor), and the two many-to-many
   relationships resolved by `T_PROGRESSO` and `T_TENTATIVA`.

## DDL: the structure

The Data Definition Language builds what the diagram describes. `01-ddl.sql`
does it in two moves. `CREATE TABLE` makes each table with its columns, types,
`NOT NULL` and defaults ([CREATE TABLE](#src-oracle-create-table)). Then
`ALTER TABLE … ADD CONSTRAINT` adds the rules: primary keys, unique keys,
checks, and last the foreign keys, which are the relationship lines of the
diagram ([ALTER TABLE](#src-oracle-alter-table)). Every constraint has a name
(`PK_ALUNO`, `FK_ALUNO_TELECENTRO`, `CK_TENTATIVA_NOTA`), so an error message
says which rule refused a row.

One clause matters for what comes later. Every primary key is declared
`GENERATED BY DEFAULT ON NULL AS IDENTITY`. The database fills the id when an
insert leaves it out, and still accepts a fixed id when one is given
([CREATE TABLE](#src-oracle-create-table)).

## DML: the data

`02-dml.sql` fills the tables with `INSERT` ([INSERT](#src-oracle-insert)): from
5 to 15 rows per table, enough for every relationship and every rule to have
something to bite on. The catalogue rows (handbooks, phases, labs) are the real
OpenLabs catalogue. The people and grades are simulated, with e-mails on the
reserved `example.com` domain. The order follows the foreign keys: parents
before children, associative tables last. The data is chosen to exercise the
schema. Two learners are inactive, five have no attempt, one learner retried an
assessment, and some e-mails are NULL, so each query has a case to show.

## DQL: the questions

`03-dql.sql` asks three questions a telecentre actually has. Each one is a
`SELECT`, and the database applies its clauses in a fixed order: it joins,
filters with `WHERE`, groups, and only then sorts ([SELECT](#src-oracle-select)).

| Question | Technique | Answer on the sample data |
| --- | --- | --- |
| Which telecentre does each learner study at? | `INNER JOIN` of two tables | 12 rows |
| How many active learners does each telecentre serve, and since when? | `INNER JOIN` + `COUNT`, `MIN`, `MAX` and `GROUP BY` | 5 groups |
| Which active learners never took an assessment? | `LEFT OUTER JOIN` + `WHERE … IS NULL` + `ORDER BY` | 3 learners |

The second query is the impact indicator. `COUNT`, `MIN` and `MAX` collapse
each telecentre's learners into one row ([aggregate functions](#src-oracle-aggregate)).
The third only works with an outer join, because the learners it looks for are
exactly the ones without a partner.

## The same tables, from an API

A Java API (Spring Boot) reads and writes this same schema. `GET /alunos/{id}`
is a `SELECT … WHERE id_aluno = :id`. `POST /alunos` is an `INSERT` without
`id_aluno`, and the identity column answers with the next number. `DELETE
/alunos/{id}` is refused with `ORA-02292` while the learner has progress rows,
and the API turns that into an HTTP error instead of deleting history. The
diagram, the scripts and the API describe one database. When a column changes,
it changes for all three.

> [!deeper] Logical model or relational model: which diagram?
>
> Data Modeler keeps both. The logical model has entities and relationships;
> the relational model has tables, columns, and the foreign key columns that
> implement each relationship ([Data Modeler](#src-data-modeler)). Importing
> `01-ddl.sql` produces the relational model directly, with every table,
> attribute, primary key, foreign key and relationship line, and the logical
> model can be engineered from it. The relational one is the one that shows
> the foreign key columns and the cardinality of each line together.
